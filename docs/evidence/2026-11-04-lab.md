## 2. Manual runs (not yet in the script)

### 2.1 Role-attached constraints are escaped by a role-less user (stock `users.xml`, constraints on a profile assigned to role `customer_admin`)

```
--- tenant SET max_memory_usage=0
Code: 452 ... Setting max_memory_usage shouldn't be less than 1. (SETTING_CONSTRAINT_VIOLATION)
--- tenant creates role-less user (CREATE USER esc2 ...)        -> user created
--- esc2 max_memory_usage=0                                    -> 0
--- esc2 max_threads=64                                        -> 64
--- esc2 database_replicated_allow_only_replicated_engine=0    -> false
```
After moving the same constraints into the server `default` profile, `esc2` gets `SETTING_CONSTRAINT_VIOLATION` for both. Section 1 checks this.

### 2.2 Plain `MergeTree` in a `Replicated` database with stock defaults

```
CREATE DATABASE app ENGINE = Replicated(...);  CREATE TABLE app.plain (id UInt64) ENGINE = MergeTree ORDER BY id
SELECT name, engine FROM system.tables WHERE database='app'  ->  plain  MergeTree
```
Not converted, not replicated. With `database_replicated_allow_only_replicated_engine = 1` (stock default 0) it's rejected with `UNKNOWN_STORAGE`.

### 2.6 Settings and names observed on 26.8.34

* `async_insert = 1`, `wait_for_async_insert = 1`, `insert_quorum = 0`, `insert_quorum_parallel = 1`, `mutations_sync = 0`, `alter_sync = 1` (all defaults).
* `max_server_memory_usage_to_ram_ratio = 0.9` (default).
* `max_table_num_to_throw` and `max_database_num_to_throw` exist (default 0).
* `table_engines_require_grant` is **`access_control_improvements.table_engines_require_grant`**. As a top-level element the server refuses to start (`UNKNOWN_ELEMENT_IN_CONFIG`).
* `access_control_improvements` keys present in the binary: `allow_impersonate_user`, `enable_read_write_grants`, `enable_user_name_access_type`, `on_cluster_queries_require_cluster_grant`, `readonly_restricts_set_role`, `role_cache_expiration_time_seconds`, `select_from_information_schema_requires_grant`, `select_from_system_db_requires_grant`, `settings_constraints_replace_previous`, `table_engines_require_grant`, `throw_on_invalid_replicated_access_entities`, `throw_on_unmatched_row_policies`, `users_without_row_policies_can_read_rows`.
* `default_database_engine` is obsolete (`is_obsolete = 1`), so there's no server-side way to make tenant `CREATE DATABASE` produce `Replicated`.
* `GRANT TABLE ENGINE ON Replicated` fails with `Unknown table engine Replicated`, while tenant `CREATE DATABASE x ENGINE = Atomic` requires `TABLE ENGINE ON Atomic`. With engine grants on, tenants can only create databases **without** an explicit engine (which gives Atomic).
* With `GRANT SELECT ON *.*`, a tenant can read `system.zookeeper`. `REVOKE SELECT ON system.zookeeper` (partial revoke) blocks it.
* Secrets in `S3(...)` arguments are shown as `[HIDDEN]` in `system.query_log`.
* `system.named_collections` returns nothing to a tenant without named-collection grants.
